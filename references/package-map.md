# Package map

Covers what every package and directory in the library does, in detail: the public `opm/` packages,
the Kubernetes tier, the internal packages and the test-only trees. The one-line layout is in
`AGENTS.md`.

```text
opm/
  errors/                     Verdict rows (data, no Error method) + grouped CUE diagnostics (alias as oerrors in consumers); pointer-receiver gate causes aggregating those rows, a rowless not-routable catch-all, the re-pin-core refusal of Render and the platform contracts; the fetch and resolution classification (author-defect resolution failures are never transient; the transient sentinel is network-level only; one classifier is the only place that matches registry and cue/load error text); the config-validation marker the kernel puts around the CUE error tree of values that fail the schema. Every error type here has a pointer receiver and none declares an As method (ADR-015; an architecture test in this folder scans for both)
  kernel/                     PUBLIC ENTRY POINT: the Kernel, its acquire / synthesize / validate methods and Render
  module/                     Module and instance types + value-validation accessors; the module source (staged tree, byte overlay) and its one writer
  platform/                   The platform: a CUE module importing its catalogs; Render's sole platform input
  catalog/                    The acquired #Catalog (ADR-009): metadata, package, source, plus the on-demand derivations of the contracts its transformers provide and of its committed cue.mod deps. Reads and derives; never renders, never judges
  schema/                     OPM core schema loader and cache + the CUE paths a consumer reads and the core-release constants; each decoded metadata type is declared with its artifact (module, platform, catalog)
  helper/                     OPT-IN convenience for frontends (a frontend MAY skip this entire tree; a depguard rule in .golangci.yml forbids every package outside it from importing it)
    platformmodule/           Platform CUE module from catalog coordinates (enhancement 0019): pure file generation, a once-at-generation tidy through a caller-configured modfile source, and a writer; the core pin defaults to the schema package default
  k8s/                        The Kubernetes tier beside the kernel (ADR-011, enhancement 0012). Mandatory for a Kubernetes frontend, fenced by depguard (nothing else under opm/ imports it; non-test files import only the standard library, cuelang.org/go/cue, k8s.io/apimachinery and the library's own opm/ packages, a strict allow list; never client-go, controller-runtime, Flux, a cluster client, opm/helper or opm/internal)
    health/                   Readiness evaluation (enhancement 0012). Pure: the frontend fetches every object, read after its apply and uncached. Ported from the cli with its rules and status strings unchanged; standard library and apimachinery only (its own depguard rule)
    inventory/                Inventory entries (no struct tags), identity comparison, the stale set, and the canonical digests of an inventory and of a render (enhancement 0012). Owns no wire shape
    labels/                   OPM label keys and values, the adopt annotation (written only by users, enhancement 0012). Standard library only (its own depguard rule). Names and recognises labels, never stamps them: core's CUE stamps at render
    lifecycle/                The deletion protocol (enhancement 0012, ADR-008 rules 1 to 3): a deletion plan, one action per advance call, caller-owned state with a pinned JSON encoding, and the hold-release rule. No hook semantics, no I/O, no clock, no goroutine
    object/                   Rendered objects with Kubernetes accessors, one-time export from CUE, the kind-class weight table aligned with Flux's staged apply order, and the duplicate apply-identity refusal a runtime raises between render and apply (enhancement 0015). The kernel never calls it
    ownership/                Pure per-object verdicts over a live object the frontend reads (enhancement 0012): what is safety-excluded, whether delete or apply may proceed, and why not. No input exists only to lift a refusal or a skip; the caller's own inventory record is trusted and not checked (ADR-016). Messages are worded here for both frontends
  internal/loader/            The kernel's one artifact loader: the shape gate + its four artifact specs (sentinels declared in opm/errors), the one build-and-gate step for a directory or a byte overlay, and the fetch of a published artifact by path and version. Internal: reached only through the kernel's acquire verbs
  internal/synth/             Instance synthesis: the synthesized #ModuleInstance value + its staged tree, built through the loader inside the module's own overlay. Internal: reached only through the kernel's synthesize verb; no platform synthesis
  internal/valuesfile/        The one renderer of a package file declaring the top-level `values` field, behind instance synthesis and the extra values the kernel layers onto an on-disk instance package
  internal/corepath/          The CUE paths the kernel's Go code reads on an artifact and no consumer needs; a consumer reaches those fields through the artifact accessors. Each path is declared once, here or in opm/schema, and a test in opm/schema pins the exported ones
  internal/modversion/        The library's one home for version helpers (spelling, major qualifier, SemVer validity and precedence) and the core module and language-floor constants; the only importer of golang.org/x/mod/semver (depguard rule one-semver-implementation)
  internal/cueenv/            The one CUE_REGISTRY / CUE_CACHE_DIR override (nil when nothing is overridden, else a copy of the process environment with the variables replaced or appended; never os.Setenv) every cue/load and modconfig call site under opm/ passes as its Env; and the Kernel's shared registry client (one resolver + transport per Kernel, built on first use, retried on a construction error, dropped after a failed registry call; a fresh modcache per kernel operation, so no fetch failure outlives its operation)
  internal/sourcetree/        Walking, reading and naming a module source in both modes (.cue files only, cue.mod/module.cue included), the synthetic render root and the one refusal of an in-memory build root that exists on disk; shared by the kernel's values overlay, the registry loader's staged overlay and the render stage. Writing an overlay out belongs to the module source, not this package
  internal/renderstage/       Single-build render staging (enhancement 0019): modfile intake (module.cue + the optional local-module.cue view), promotion (local replacements under the opt-in) + coverage invariant, skew comparison, the embedded CUE glue template (matching, execution, diagnostics, gate), in-memory staging under the synthetic render root (nothing written) + one cue/load build
  internal/registrytest/      Test-only in-process OCI registry serving inline #Catalog and module fixtures or a committed fixture tree; every constructor points CUE_CACHE_DIR at a private per-test module cache, so served coordinates extract fresh per test and nothing is ever deleted from the shared cache; the stand-in-core constructor also serves a stand-in opmodel.dev/core, into a cache that shares nothing
  internal/cueregression/     Canary pair for the closedness regression of the pinned CUE release
  internal/schematest/        Test-only cache helpers: one builds against the shared workspace cache (.cue-cache, the opmodel.dev tier); one hands a test its own cache whose opmodel.dev subtrees are symlinks into the shared one; one hands it a cache that shares nothing (for a served stand-in core)
adr/                          Architecture decision records (the template is inside)
openspec/                     OpenSpec proposals/specs/archives (active change workflow)
modules/                      Test-only CUE modules (opm, opm_platform) - fixtures, not shipped
testdata/                     CUE module fixtures consumed by package tests (synth fixture + test cue.mod; `parity/` is the render-parity oracle module for the parity tests in `opm/kernel/`; `render/` is the single-build render fixture set for the render tests in `opm/kernel/`: a registrytest-served catalog + module tree under `registry/`, platforms that import their catalog, an instance and per-outcome scenario packages, all pinned to the default core release and served in-process, so not discovered by the CUE tasks)
docs/getting-started.md       End-to-end embedding walkthrough
docs/design/                  CUE evaluator notes (closedness regression + canary) and historical bug records
docs/site/                    Authored site pages (diagnostics how-tos, Embed the kernel); ship in the library docs bundle, while opmodel.dev still reads them from git on main until it reads the library from bundles
docs-kit.cue                  The docs bundle config (docs-kit): the go-api source over ./opm/... and the markdown source over docs/site
.tasks/                       Task scripts, including the one that installs the pinned opm-docs into .bin/ (checksum-verified) and checks the two pins agree; catalog_opm's, byte for byte
migrations/                   Per-change migration fragments + policy (dormant through beta until GA, CI-enforced after - ADR-004; beta notes live in the CHANGELOG footer, ADR-010)
.cue-cache/                   Gitignored shared CUE module cache: the opmodel.dev tier (core + GHCR catalogs) every test and test process reads; served fixtures live in per-test private caches, and nothing in the test tree deletes from it
```
