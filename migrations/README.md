# Migration documentation

Per-change migration recipes for the library's public Go API and the OPM contract it ships.
[`CHANGELOG.md`](../CHANGELOG.md) (generated by release-please) owns the per-version summary of
*what* shipped; this directory owns the *how-to-migrate* detail, one file per change.

## Status: dormant until GA

The library is pre-GA. Until the first GA release:

- **No migration fragments are required or written.** Breaking changes are recorded by
  release-please in `CHANGELOG.md` and, with full design context, in
  `openspec/changes/archive/`.
- Both consumers (`cli`, `opm-operator`) live in this workspace and migrate in the same
  coordinated PR wave, so a standing recipe document has no audience yet.

From the first GA release onward this directory becomes mandatory and CI-enforced. The
enforcement design is recorded in [ADR-004](../adr/004-migration-docs-structure.md).

## Layout (armed at GA)

```text
migrations/
  README.md               this policy + the generated index below
  unreleased/<slug>.md    one fragment per breaking change, authored in the breaking PR
  vX.Y.Z/<slug>.md        graduated fragments; the release job moves unreleased/* here
```

- `<slug>` is the OpenSpec change slug, shared with the breaking commit's
  `Migration: <slug>` trailer. One fragment per change.
- **Authors never write version numbers.** release-please computes the next version at
  release time; the release job performs `git mv migrations/unreleased/* migrations/vX.Y.Z/`
  and regenerates the index. (Sequence-number prefixes were rejected: two parallel PRs
  would claim the same number.)
- Read the releases in order via the index below; raw directory listings do not sort
  SemVer correctly (`v10` before `v2`).

## Fragment format

```markdown
---
slug: <openspec-change-slug>
impact: breaking | additive
---

## What broke

One paragraph: the removed/changed surface and why.

## Migration recipe

Old-vs-new table or diff. Name the affected downstream call sites (`cli`, `opm-operator`)
when known.
```

## Enforcement (armed at GA)

- Every breaking PR (`type!:` / `BREAKING CHANGE:`) carries a `Migration: <slug>` trailer
  in its description; `Migration: none — <reason>` is the escape hatch for breaks that need
  no consumer action.
- A PR-time gate requires the trailer and a matching `migrations/unreleased/<slug>.md` in
  the diff. A release-time backstop re-derives the breaking set for the release range and
  blocks the release on any uncovered slug, then graduates the fragments.
- A `migration` skill authors the fragment alongside the breaking change.
